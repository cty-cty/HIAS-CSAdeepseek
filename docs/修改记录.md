## 2026-09-14

需求背景：线上站点 `https://cty-cty.github.io/HIAS-CSAdeepseek/` 需要一个「意见反馈 / 留言」入口，
方便同学报告课程数据错误、提功能建议。站点是 GitHub Pages **纯静态托管**（没有服务器、没有数据库），
而且项目要求离线单文件版完全可用、构建产物禁止外部脚本，因此采用
**「站内表单 + 本机留档 + 一键带到 GitHub Issue 提交」**的方案：零后端、零第三方依赖、离线也能用。

**涉及文件**：`app/feedback.ts`（新增）、`app/course-explorer.tsx`、`app/globals.css`、`tests/feedback.test.ts`（新增）、`package.json`

  - `createFeedbackEntry` 统一归一化文本（`\r\n` → `\n`、合并连续空行、去首尾空格），
    `now` / `id` / `context` 可注入，便于确定性测试；
  - `buildIssueUrl` 用 `URLSearchParams` 生成
    `https://github.com/cty-cty/HIAS-CSAdeepseek/issues/new?title=…&body=…&labels=feedback`，
    并提供 `isIssueUrlTooLong` 处理超长链接；

### 2. 修复「培养设置」弹窗整体歪斜（`.ring-1` / `.ring-2` 与 Tailwind 工具类撞名）

**问题**：首次打开页面弹出的「培养设置」窗口整体歪斜（实测被旋转约 27°、斜切约 8°），高度也被压成 225px。

**根因**：`app/globals.css` 里为 DeepSeek 桌面页写的装饰圆环类叫 `.ring-1` / `.ring-2`，
而 shadcn 组件的 `ring-1` / `ring-2` 是 Tailwind 的 ring 宽度**工具类**。
`@import 'tailwindcss'` 生成的工具类位于 `@layer utilities`，而**未分层的普通类会盖住分层样式**，
于是所有带 `ring-1` 的组件（`DialogContent`、`AlertDialogContent`、`Popover`、`Select` 等）
都被强行套上 `width:225px;height:225px;transform:rotate(27deg) skew(-8deg)`。
实测 `getComputedStyle(弹窗).transform` = `matrix(0.891007, 0.45399, -0.579213, 0.827202, 0, 0)`，
正是 `rotate(27deg) skew(-8deg)`；`transform-origin` 为 `240px 112.5px` 也印证布局高度被压到 225px。

**涉及文件**：`app/globals.css`、`app/deepseek/page.tsx`、`tests/css-guard.test.ts`（新增）、`package.json`

**实现逻辑**：
- 装饰类改名为 `.dsh-ring-1` / `.dsh-ring-2`，`app/deepseek/page.tsx` 同步改名，桌面页视觉不变；
- 在该样式块顶部写明「新增类名一律带 `dsh-` 前缀」并记录本次事故原因，避免回退；
- 新增 `tests/css-guard.test.ts`：解析 `globals.css` 的**裸类选择器**（整条选择器就是单个 `.类名`），
  断言其中没有 Tailwind 工具类命名空间（`ring-*`、`shadow-*`、`p-*`、`mt-*`、`h-*` 等）的名字；
  再反向校验 shadcn 组件实际用到的 `ring-*` 没有被全局类劫持。`.plan-summary .mt-6`、
  `.hero-panel > div.relative` 这类**带祖先限定**的写法只在那棵子树生效，不算撞名，测试不会误报。

**用户可见变化**：「培养设置」以及清空确认等弹窗恢复正常——居中、按内容撑高、不再旋转斜切；
同时 shadcn 组件恢复本应有的 1px ring 描边。

**兼容性**：纯类名重命名，不改动数据、localStorage 键与构建流程；线上版与离线版一并生效。

### 1. 修复线上静态资源全部 404（部署链路）

**问题**：线上 `https://cty-cty.github.io/HIAS-CSAdeepseek/` 的
`/sw.js`、`/manifest.webmanifest`、`/favicon.svg` 均返回 404。

**根因**：`pages.yml` 只把离线版单文件 HTML 拷成 `_site/index.html`，没有发布 `public/`；
同时离线单文件 HTML 的 `<head>` 完全没有引用 favicon / manifest / 图标。

**涉及文件**：`.github/workflows/pages.yml`、`scripts/package-offline.mjs`、`scripts/validate-offline.mjs`、`public/manifest.webmanifest`、`public/sw.js`、`app/offline-registration.tsx`、`offline/main.tsx`、`scripts/generate-icons.mjs`（新增）、`public/icon-192.png`、`public/icon-512.png`、`public/icon-maskable-512.png`（新增）

**实现逻辑**：
- `pages.yml` 增加 `cp -r public/* _site/`。
- `package-offline.mjs` 在生成的 `<head>` 中内联 favicon（data URI，离线/在线都可用），并加入
  `manifest`、`apple-touch-icon`、description、Open Graph 与 Twitter 卡片（`og:image` 指向 `./og.png`）。
- 所有资源引用改为**相对路径**（`./…`），因为 GitHub Pages 部署在 `/<repo>/` 子路径下，绝对路径 `/sw.js` 会指到域名根。
- `validate-offline.mjs` 的「外部样式」检查收窄为只拦 `<link rel="stylesheet">`，不再误报 icon/manifest。
- `offline/main.tsx` 挂载 `<OfflineRegistration />`，让线上单文件版真正注册 Service Worker；
  `sw.js` 改用 `self.registration.scope` 计算相对资源，缓存版本升到 v16。
- `manifest.webmanifest` 补齐 192/512/maskable PNG 图标（`scripts/generate-icons.mjs` 用纯 Node 生成，无第三方依赖）。

**用户可见变化**：浏览器标签页出现 favicon；站点可「添加到主屏幕」；首次访问后支持离线打开。

**兼容性**：离线单文件仍可脱离服务器直接用浏览器打开（favicon 已内联）；localStorage、备份、导出流程未改动。

### 6. 课程数据导入模块：保留教学班

**背景**：审计点名的两个高优先级问题——导入会把同一门课的不同正式教学班（`-01`/`-02`）合并成一条，
导致无法换班、班次丢失；计划记录与正式记录同时存在时重复显示或丢弃用户选课。

**涉及文件**：`app/course-data.ts`（新增）、`tests/course-data.test.ts`（新增）

**实现逻辑**（口径照参考版 `coursesShareIdentity`）：
- `officialBaseCode()`：占位编码（`SP2027-xxx`）与空值一律视为「材料未给出正式编码」；
- `coursesShareIdentity()`：英语按 family 特判 → 双方都有正式编码则比较去掉班次后缀的基础编码 →
  只要一方没有正式编码，就退化为「标准化课程名 + 所属专业」比较。
  这是**计划课程能被正式课表升级**的关键；
- `isPlannedCourse()`：显式正式状态优先，缺状态字段的旧格式记录按正式课程处理；
- `mergeCourseRows()`：正式班次之间只有同 id 或同班次编码才算重复（**不再按课程身份合并班次**）；
  正式记录覆盖同课程的计划占位；计划记录之间才按课程身份去重；
- `reconcileCourseUpdate()`：增量合并，未匹配的旧课程与旧选课一律保留并回报，
  匹配到多个班次只产出 `sectionChoices` 提示、不替用户决定，学位属性随课程身份迁移。

**测试结果**：`tests/course-data.test.ts` → 通过 19 项，失败 0 项。
其中 S1 直接回归「两个正式教学班都保留」，S2 覆盖计划→正式升级，S7 覆盖未匹配选课保留。

### 9. 培养进度跨学期累计（推荐侧对齐）

**背景**：体检侧已经用 `programCourses`（历史 + 其它学期已选 + 本学期已选）计算培养进度，
但推荐引擎只收到本学期 `selectedCourses` + `historicalRecords`，**读不到其它学期已选**，
于是可能把「已经在春季规划过的课」当成缺口，在当前学期重复推荐。

**涉及文件**：`app/recommendation-engine.ts`、`app/course-explorer.tsx`、`tests/program-rules.test.ts`

**实现逻辑**：
- `RecommendationRequest` 新增可选 `otherTermCourses: CourseRecord[]`。
- `buildCandidates()`：把其它学期已选的课程身份加入 `otherTermCanonical`，
  同课程不再作为当前学期候选（与既有的 `selectedCanonical` / `historyCanonical` 并列）。
- `projectState()`：新增可选参数 `otherTermCourses`（放在参数表末位，保持既有调用兼容），
  把它并入 `calculateCreditSummary.selectedCourses`、`getPlanCourseCounts.courses`
  与 `collectConfirmedDegreeNames`，使推荐方案的缺口投影与体检口径一致。
  **注意：学期有效学分仍只统计当前学期**（`effectiveCredits` 未改），排课冲突也只看当前学期。
- `course-explorer.tsx`：两处推荐请求（`buildCandidates` / `generateRecommendationPlans`）
  传入 `otherTermCourses: carriedTermCourses`，并补进 `useMemo` 依赖。

**测试结果**：新增 S25 / S25b 两项对照断言——其它学期已规划的课程不再出现在候选里，
不传该字段时同一门课仍可候选。`tests/program-rules.test.ts` → 通过 156 项。

### 10. 课程数据导入接线（保留教学班 + 增量合并）

**背景**：原导入流程把整学期数据集**整体替换**，选课只按「完整编码字符串」匹配，
新数据里没有的旧课程与旧选课会被丢弃（仅提示数量）；春季计划→正式的升级还依赖一段手工匹配。

**涉及文件**：`app/course-explorer.tsx`

**实现逻辑**：
- `handleCourseDataImport` 改接 `reconcileCourseUpdate(旧数据, 导入数据, 旧选课, 旧属性)`：
  - **保留不同教学班**：同一门课的 `-01`/`-02` 分别留下，导入后仍可换班；
  - **计划→正式升级**：正式课表记录替换同课程的计划占位，原先的手工 `officialCode` / `canonicalCourseId`
    匹配逻辑被统一的身份匹配取代；
  - **增量合并**：新数据里没有的旧课程与旧选课按原样保留，不再静默丢失；
  - **属性迁移**：学位属性随课程身份迁移到新班次。
- 提示信息改为回报「保留的已选门数 / 升级门数 / 多班次待确认清单 / 未匹配保留门数」。

**用户可见变化**：更新同一学期课程数据时不再丢课程与选课；匹配到多个教学班会明确列出待确认班次。

**已知取舍**：更新是**增量合并**而非整体替换（与参考版一致）。因此如果新数据删掉了某门课，
旧记录会保留并在提示里标明；如确需整体替换，应另行提供「清空该学期再导入」的入口。
